## 3. Fillers
**Detector** (`packages/media/src/voiced.ts`): short-time energy per 20 ms; a stretch counts when it is clearly above the quiet floor of the gaps and not much quieter than speech; length 0.15-1.2 s (longer ones are counted as "too long", never offered). It cannot tell an "um" from a breath, a laugh, a cough or room noise: every marker carries level, zero-crossing rate, a "touches a word edge" flag and a LOW confidence (50-600 permille; 450 = speech-level and periodic, 350 = typical, 200 = noise-like or quiet).
**On the old recording** (`docs/raw/m4_voiced_gaps_old_recording.txt`): **29 markers**, 0 "too long". Lengths 0.16-1.04 s. Confidence: 2 at 45%, 21 at 35%, 6 at 20%. 27 of 29 touch a word edge (expected for a filler between two words, but also what a word's tail would look like). ## 5. Gemini fallback
- **Name check:** `gemini-3.5-flash-lite` exists (HTTP 200 on a first call; `modelVersion` echoed back). No error.
- **Design:** the model sees only the instruction and a small summary (length, effect ids/kinds/states, music on/off; no transcript, no media). It may only return `{"commands":[...]}` from a closed list (zod, max 5, ranges checked); invalid output, unsupported requests and engine refusals are rejections with the reason and the timeline unchanged. The commands become sentences ("cut 0:30.000-0:40.000") that the rules parser and engine apply, and the answer says how it was interpreted. Temperature 0, JSON output, key in a header only and scrubbed from any error text (tests with a fake server check the key never appears).
- **Cache:** `llm_cache` key = hash of provider, model, prompt version, normalised instruction and timeline context; a replay needs no network. Run 3 of session 23 answered all 4 steps from the cache in 16-70 ms with the same timeline hashes as before.
- **Real results** (`docs/raw/m4_llm_session*`): "get rid of the stretch between half a minute and forty seconds" -> `cut 0:30.000-0:40.000` (applied); "make the clip from a minute twenty to a minute thirty run twice as fast" -> `speed up 1:20.000-1:30.000 by 2x` (applied); "put a spinning logo in the corner" -> rejected ("not supported by the available commands").
- **Latency can exceed 3 s, by a lot.** Probe with the real prompt (`docs/raw/m4_llm_latency_probe.txt`): 18.4 s, 33.9 s, 35.9 s, 0.9 s, 17.7 s (and 0.75-1.5 s in the session runs; the first session run timed out on 3 of 4 steps). I did NOT build a 202 + job path. Instead the call has a timeout (`LLM_TIMEOUT_MS`, default 2.5 s); on a timeout the answer is a rejection saying the model did not answer in time and to repeat in a few seconds, and the reply that arrives later is still stored, so the repeat is a cache hit (shown by tests with a delayed mock; with the real model it worked for steps 1-2 of run 2 but not for a repeat whose timeline context had changed, which is a different cache key). A real job path would be needed to make this reliable.
- **Cost:** the manifest reports tokens and an ESTIMATE at the paid-tier rates ($0.30 / $2.50 per 1M tokens): about 556 input + 25 output tokens = **$0.00023 per call**. Requests made in this milestone: 1 first ping (8 tokens), 5 successful and 3 rejected (HTTP 400, my invalid thinking parameter) probe calls, and about 4 + 4 calls in the first two session runs; run 3 made none. Roughly 14 billed-or-free requests, about $0.003 at paid rates; `llm_cache` holds 4 distinct replies (2,226 input and 98 output tokens, about $0.0009).

## 6. Advanced behaviours (all in the rules parser: no network, deterministic)
- **"make it shorter"** -> question with measurable options and the time each saves ("remove the 9 silences longer than 1 s (saves about 27.2 s)"); nothing cut before the answer.
- **"remove the boring part"** -> says it cannot judge boring, states the assumption, offers the longest pause, the slowest stretch of speech and the stretch with the most filler/low-confidence words, each with times and the signal. On the old recording: 1:52.8-2:01.6 (8.8 s of silence), 1:50-2:05 (0.5 words/s), 1:00-1:15 (11 such words).
- **"that caption"** with two captions asks which; **"put back what I removed"** lists each removed edit; **"make it bigger"** with no caption is rejected with the reason (session 25, real run).
- **Two speakers:** "remove everything the guest says about their old job": the first speaker heard is assumed to be the host and the answer SAYS so ("Assuming Speaker A (the first speaker I heard) is the host and Speaker B is the guest."); only the guest's lines on the topic are cut, and it ASKS about the host's lead-in ("So tell me about your old job." at 0:05.5): option 1 keeps it, option 2 removes it. With three or more speakers it asks "Speaker A, Speaker B or Speaker C?" with a sample line each. With one speaker it rejects. An explicit "speaker B" needs no assumption. Warnings when cut words have an uncertain speaker label (possible swap) or overlap another speaker. **I read your two rules (assume the first speaker is the host / ask which speaker is the guest if unknown) as: two speakers -> assume and say so; three or more -> ask.**
