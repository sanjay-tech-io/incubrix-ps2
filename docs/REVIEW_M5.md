## 2. OpenTimelineIO export
**Design.** `packages/otio` turns the materialized timeline into plain integers (`buildOtioPayload`, pure, uses the engine's pieces); `services/otio` builds the OTIO objects with the library and writes the file. Provider switch `OTIO_PROVIDER=http|mock` (`mock` writes the same JSON shape by hand, so the API works with no service; a compose test loads the mock's output with the library too).

**Convention (what a reader of the file must know).**
- Time unit = frames of the source's frame rate (exact rational, e.g. 30000/1001). A source with no frame rate would use microseconds (tested in Python only).
- One clip per engine *piece* (a stretch of source at one constant rate), in **output order**, on a video track `V1` and an audio track `A1` (the same clips).
- `clip.source_range` = (start in the **source**, duration in the **output**). A sped-up or slowed clip has a `LinearTimeWarp` with `time_scalar` = the speed (2.0, 0.5, ...), so it reads `speed x duration` of source. This way the track is exactly as long as the rendered video, with the engine's cumulative frame rounding kept. NLEs differ in how they read `LinearTimeWarp`; **I did not open the file in any editor.**
- Captions and text overlays, auto-caption cues, mutes and bleeps are **markers** on `V1` at output time (marker colour = nearest OTIO colour to the caption colour; the real colour and text are in the marker metadata). A caption whose words are all cut is inactive and has no marker (it stays in the log; its id is listed in the timeline metadata).
- Each clip's metadata keeps the exact source span in microseconds and the exact speed as a fraction; the timeline metadata has the timeline hash, the source sha256, the exporter version, `ai_generated`, and the music settings (**the music itself is not exported**).
- Media reference = the original's file name only (no URL), with the sha256 in its metadata.

## 3. Speaker-label swap detection
**Rule** (`services/asr/asr/swap.py`, pure Python lists, no model): a turn is judged only if it has an embedding and is at least `DIARIZATION_SWAP_MIN_TURN_S` (1.5 s) long. Speaker centroid = length-weighted mean of unit-length turn embeddings. The turn's *own* similarity uses the **leave-one-out** centroid (the turn does not vouch for itself). Flag when `best other similarity - own similarity > DIARIZATION_SWAP_MARGIN` (0.05, cosine). A speaker with a single judged turn cannot be checked and is reported as not testable. Embeddings: WeSpeaker ResNet34, the same model the clustering uses (`SherpaDiarizer.turn_embeddings`). The service reports `settings.diarization.label_swap` (turns checked / skipped / flagged, with similarities) in its response; the transcript cache key changed to v3, so videos ingested before M5 have no flags until they are ingested again.

**Tests.**
- `services/asr/tests/test_swap.py` (13): synthetic vectors, a label swapped on purpose is flagged and only that turn, both directions, margin respected, short / missing / single-turn cases, order independence, words in a flagged turn get the flag and keep their label, service wiring, settings validation.
- Engine, nlu, worker and API tests: the flag reaches the atoms, intake warns ("N word(s) may have the wrong speaker label..."), an edit touching them warns ("possible speaker-label swap"), an edit elsewhere does not, and speaker-scoped removal ("remove everything the guest says...") names the count.
- **Real models on the by-construction two-voice clip** (`services/asr/spike/make_two_voice.sh`, espeak-ng voices; `docs/raw/m5_swap_real_run.txt`, `m5_swap_real_pytest.txt`): the diarizer found 6 turns of the 2 speakers (2 requested). Faithful labels: 0 of 6 flagged (own similarity 0.96-0.99, other 0.72-0.77). Relabelling **each** turn in turn to the other speaker: **6 of 6 detected, 0 other turns flagged** (own 0.72-0.77 vs other 0.96-0.99).

**Limits (please read).**
- This is two *synthetic* voices that sound very different (similarity gap about 0.2). It says nothing about two real people with similar voices, noisy audio, or phone audio. The default margin 0.05 and minimum turn 1.5 s were chosen by me and checked only on this clip.
- If the diarizer finds ONE cluster for two speakers (it did with default settings on the earlier synthetic clip, REVIEW_INFRA), there is nothing to compare and nothing is flagged.
- A turn where two people talk at once embeds a mix of voices; the flag is a warning, not a verdict. The real-model pytest is skipped unless `DIARIZATION_TEST_AUDIO` is set (the test image has no espeak to make the clip), so it is **not** part of `docker compose run --rm tests`.

## 4. The scenario pack and CI
**What it is.** `scenarios/s01..s48_*.yaml`: session files (same format as `sessions/`, minus `video`, plus `fixture` and `brief`) run by `apps/api/test/scenarios.test.ts` through the same HTTP session runner a user runs. The mock ASR returns a hand-written transcript (`apps/api/test/scenario_fixtures.ts`: the engine's 3:20 worked-example fixture, a two-speaker one with uncertain / overlapping / swap-flagged words, a low-confidence one, a short phone clip with variable frame rate, a clip without audio) and the video is a generated clip. So the scenarios test **editing** (parsing, engine, API, jobs, render), not speech recognition. 7 scenarios render with real ffmpeg (frame count checked against the timeline, original sha256 re-checked). Coverage by the brief: the worked example (8 steps, hand-computed lengths); every line of the "hard cases" paragraph (caption cut and restored, reorder then mute, filler removal into a bleep, `remove 0:30-0:40` twice, caption at 5:00, "80 seconds" / "a minute twenty" / "the last 10 seconds", undo second-to-last cut keeping the music, "make it bigger" without a caption, "after I say thanks" said four times, 10x, "cut everything", three parts with one impossible, two speakers with label swap and overlapping speech, music, variable frame rate); Advanced (partial cut of a captioned phrase, 0.7 s minimum, overlapping speed, repeated instructions, ambiguity with options, meaning search, "make it shorter", "the boring part", "put back what I removed", "that caption", protected pauses, guest / host); Outstanding (low-confidence warning, label swap and overlap warnings, no audio, VFR). Plus determinism: six scenarios are run twice more and every step's `timeline_hash` must be identical.

**Format additions** (runner, `apps/cli/src/format.ts`): `expect_warning`, `expect_no_warning`, `expect_text` (regular expressions, case-insensitive), `expect_options` (exact count) and `expect_hash_unchanged` (repeat instructions and clarification turns must not change the timeline). Tested in `runner.test.ts`, including that a mismatch fails the step with a message.
